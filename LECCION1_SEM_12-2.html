Ejercicio 1. Consultar el modelo de recuperación

SELECT name, recovery_model_desc
FROM sys.databases
WHERE name = 'GradosTitulos';
  • sys.databases es una vista del sistema con todas las bases del servidor.
  • recovery_model_desc muestra el modelo de recuperación: SIMPLE, FULL o BULK_LOGGED.
  • El WHERE filtra solo GradosTitulos.

Por qué importa

El modelo decide qué respaldos puedes hacer. Si está en SIMPLE, no puedes hacer backups del log de transacciones, y por tanto tampoco recuperar hasta un momento exacto. Para eso necesitas FULL (o BULK_LOGGED).

Ejercicio 2. Consultar el tamaño de la base de datos

USE GradosTitulos;
GO
EXEC sp_spaceused;
GO
  • USE GradosTitulos; cambia el contexto a esa base.
  • GO separa lotes de instrucciones (es un comando de SSMS, no de T-SQL).
  • sp_spaceused es un procedimiento almacenado que muestra el tamaño total, el espacio usado y el espacio libre.

Por qué importa

El tamaño te dice cuánto pesará un backup completo y cuánto espacio necesitas en disco (por ejemplo en C:\Backups). Influye en el RTO: una base más grande tarda más en restaurarse.

Ejercicio 3. Identificar las tablas más importantes

SELECT s.name AS Esquema, t.name AS Tabla
FROM sys.tables t
INNER JOIN sys.schemas s
    ON t.schema_id = s.schema_id
WHERE s.name IN ('Academico','Tramite','Evaluacion','Documento','Seguridad')
ORDER BY s.name, t.name;
GO
  • sys.tables lista las tablas y sys.schemas los esquemas.
  • El INNER JOIN une ambos mediante schema_id, para saber a qué esquema pertenece cada tabla.
  • AS Esquema y AS Tabla son alias para que las columnas se lean mejor.
  • El WHERE ... IN (...) deja solo los esquemas críticos del proyecto.
  • ORDER BY ordena por esquema y luego por tabla.

Por qué importa

Te permite ver qué información hay que proteger primero: estudiantes, trámites, evaluaciones, documentos y seguridad.
