Paso 0. Preparación: carpeta de respaldos

Objetivo

Crear la carpeta donde se guardarán los respaldos y darle permiso de escritura a la cuenta de servicio de SQL Server.

0.1 Crear la carpeta

En la unidad C: se crea la carpeta Backups, con la ruta C:\Backups. También se puede crear desde CMD con mkdir C:\Backups.

0.2 Consultar la cuenta de servicio de SQL Server

SELECT servicename, service_account
FROM sys.dm_server_services;
  • La cuenta del motor de base de datos, fila SQL Server (MSSQLSERVERDEV), es NT Service\MSSQL$MSSQLSERVERDEV.
  • Esa es la cuenta que escribe los archivos de respaldo.

0.3 Dar permisos sobre la carpeta

  1. Clic derecho en C:\Backups, Propiedades, pestaña Seguridad, Editar y Agregar.
  2. En Ubicaciones elegir el equipo LAB05-PC14.
  3. Escribir NT Service\MSSQL$MSSQLSERVERDEV y pulsar Comprobar nombres.
  4. Aceptar y marcar Modificar (o Control total) en la columna Permitir; luego Aplicar.

Pasos 1 y 2. Verificar el estado y el modelo de recuperación

Objetivo

Comprobar que GradosTitulos esté Online y conocer su modelo de recuperación. Un solo script resuelve ambos pasos.

Conexión a la instancia

En SSMS, ventana Connect to Server: Server type Database Engine, Server name LAB05-PC14\MSSQLSERVERDEV, Authentication Windows Authentication, y clic en Connect.

SELECT
    name AS BaseDatos,
    state_desc AS Estado,
    recovery_model_desc AS ModeloRecuperacion
FROM sys.databases
WHERE name = 'GradosTitulos';
GO
BaseDatosEstadoModeloRecuperacion
GradosTitulosONLINEFULL

Análisis

La base de datos está disponible. El modelo FULL permite hacer backups completos, diferenciales y del LOG, por lo que el paso 5 se puede ejecutar.

3

Paso 3. Backup completo (FULL)

Objetivo

Crear la copia base de la que dependen el backup diferencial y el del LOG.

USE master;
GO
BACKUP DATABASE GradosTitulos
TO DISK = 'C:\Backups\GradosTitulos_FULL_20261118_1815.bak'
WITH
    CHECKSUM,
    STATS = 10;
GO
InstrucciónFunción
BACKUP DATABASECrea la copia de seguridad de la base de datos.
TO DISKIndica la ruta y el nombre del archivo de respaldo.
CHECKSUMVerifica la integridad de los datos durante la copia.
STATS = 10Muestra el avance cada 10 %.
4

Paso 4. Backup diferencial

Objetivo

Guardar solo los cambios hechos desde el último backup completo. Requiere que ya exista un backup completo.

USE master;
GO

BACKUP DATABASE GradosTitulos
TO DISK = 'C:\Backups\GradosTitulos_DIFF_20261118_1820.bak'
WITH
    DIFFERENTIAL,
    CHECKSUM,
    STATS = 10;
GO

La única opción nueva es DIFFERENTIAL, que indica que el respaldo será diferencial.

5

Paso 5. Backup del registro de transacciones (LOG)

Objetivo

Respaldar el registro de operaciones para poder recuperar datos hasta un momento específico. Se cumplen las dos condiciones: el modelo es FULL (paso 2) y existe un backup completo previo (paso 3).

USE master;
GO

BACKUP LOG GradosTitulos
TO DISK = 'C:\Backups\GradosTitulos_LOG_20261118_1830.trn'
WITH
    CHECKSUM,
    STATS = 10;
GO
  • BACKUP LOG respalda el registro de transacciones y no las tablas.
  • La extensión .trn es la convencional para backups de log.
  • Mensaje: BACKUP LOG successfully processed 5 pages in 0.004 seconds (8.300 MB/sec), finalizado el 18/11/2026 a las 18:21:15.
6

Paso 6. Verificar los archivos con RESTORE VERIFYONLY

Objetivo

Comprobar que los tres archivos se pueden leer y no están dañados, sin restaurar la base de datos.

USE master;
GO

-- Verificar el backup completo
RESTORE VERIFYONLY
FROM DISK = 'C:\Backups\GradosTitulos_FULL_20261118_1815.bak'
WITH CHECKSUM;
GO

-- Verificar el backup diferencial
RESTORE VERIFYONLY
FROM DISK = 'C:\Backups\GradosTitulos_DIFF_20261118_1820.bak'
WITH CHECKSUM;
GO

-- Verificar el backup del LOG
RESTORE VERIFYONLY
FROM DISK = 'C:\Backups\GradosTitulos_LOG_20261118_1830.trn'
WITH CHECKSUM;
GO

SQL Server mostró tres veces The backup set on file 1 is valid., una por cada archivo, y la consulta se ejecutó correctamente (18:22:09).

Importante

RESTORE VERIFYONLY no sustituye una restauración real. Comprueba que el conjunto de backup se puede leer y es válido; para comprobar que sirve para recuperar la base se deben hacer restauraciones de prueba en un entorno separado.

Paso 7. Consultar el historial de backup en msdb

Objetivo

Ver el registro de los respaldos hechos, que SQL Server guarda en la base de datos del sistema msdb.

SELECT
    database_name AS BaseDatos,
    CASE type
        WHEN 'D' THEN 'COMPLETO'
        WHEN 'I' THEN 'DIFERENCIAL'
        WHEN 'L' THEN 'LOG'
        ELSE type
    END AS TipoBackup,
    backup_start_date AS FechaInicio,
    backup_finish_date AS FechaFin,
    backup_size / 1024.0 / 1024.0 AS TamanoMB,
    physical_device_name AS ArchivoBackup
FROM msdb.dbo.backupset AS B
INNER JOIN msdb.dbo.backupmediafamily AS M
    ON B.media_set_id = M.media_set_id
WHERE database_name = 'GradosTitulos'
ORDER BY backup_finish_date DESC;
GO
