Módulo 02

Seguridad, roles y asignación de permisos

ESPEJO COSME JORCH
Emblema del módulo: escudo y llave de seguridad (ilustrativo)

Propósito y escenario

Implementar autenticación y autorización en SQL Server con logins, usuarios, roles de base de datos y permisos específicos sobre GradosTitulos. Se crea una cuenta para un analista académico que consulta trámites sin modificar registros ni acceder libremente a la información de seguridad.

Modelo RBAC

Un usuario puede tener uno o varios roles; un rol, uno o varios permisos.
Seguridad.Usuario → UsuarioRol → Rol → RolPermiso → Permiso
ElementoNivelFunción
LoginServidorAutenticarse en SQL Server
UserBase de datosAcceder a una BD
RoleBase de datosAgrupar privilegios
PermissionObjeto/esquemaOperaciones permitidas
Roles institucionales: ADMINISTRADOR, SECRETARIA, COORDINADOR, DOCENTE, ASESOR, JURADO, ESTUDIANTE, DECANO, CONSULTA.
ACT 1

Crear un login de servidor

USE master;
CREATE LOGIN login_analista_grados
WITH PASSWORD = 'Cambiar_EstaClave#2026', CHECK_POLICY = ON, CHECK_EXPIRATION = ON;
SELECT name, type_desc, is_disabled, create_date
FROM sys.server_principals WHERE name = 'login_analista_grados';
IMPORTANTE: contraseña solo de laboratorio; no la subas a repositorios.
ACT 2

Crear el usuario de base de datos

USE GradosTitulos;
CREATE USER usr_analista_grados FOR LOGIN login_analista_grados
WITH DEFAULT_SCHEMA = dbo;
ACT 3

Crear un rol personalizado

CREATE ROLE rol_analista_grados AUTHORIZATION dbo;
ACT 4

Asignar el usuario al rol

ALTER ROLE rol_analista_grados ADD MEMBER usr_analista_grados;
ACT 5

Asignar permisos con GRANT

GRANT SELECT ON OBJECT::Tramite.Tramite TO rol_analista_grados;
GRANT SELECT ON OBJECT::Tramite.Pago TO rol_analista_grados;
GRANT SELECT ON OBJECT::Tramite.ObservacionTramite TO rol_analista_grados;
ACT 6

Aplicar DENY y REVOKE

DENY INSERT, UPDATE, DELETE ON OBJECT::Tramite.Tramite TO rol_analista_grados;
DENY SELECT ON OBJECT::Seguridad.AuditoriaSeguridad TO rol_analista_grados;
REVOKE SELECT ON OBJECT::Seguridad.AuditoriaSeguridad FROM rol_analista_grados;
OBSERVACIÓN: REVOKE no concede acceso; solo elimina la concesión o denegación explícita.
ACT 7

Consultar permisos efectivos

SELECT DP.name AS NombreRol, P.permission_name AS Permiso, P.state_desc AS Estado,
       OBJECT_SCHEMA_NAME(P.major_id) AS Esquema, OBJECT_NAME(P.major_id) AS Objeto
FROM sys.database_permissions P
JOIN sys.database_principals DP ON P.grantee_principal_id = DP.principal_id
WHERE DP.name = 'rol_analista_grados';
ACT 8

Validar con EXECUTE AS

EXECUTE AS USER = 'usr_analista_grados';
SELECT TOP (10) * FROM Tramite.Tramite;            -- permitida
UPDATE Tramite.Tramite SET Observaciones='Prueba' WHERE IdTramite=-1; -- denegada
SELECT TOP (10) * FROM Seguridad.AuditoriaSeguridad; -- denegada
REVERT;
ACT 9

Integrar el rol SQL con el catálogo RBAC

IF NOT EXISTS (SELECT 1 FROM Seguridad.Rol WHERE NombreRol='ANALISTA_GRADOS')
  INSERT INTO Seguridad.Rol (NombreRol, Descripcion, EsSistema, Activo)
  VALUES ('ANALISTA_GRADOS','Consulta y análisis de trámites académicos.',0,1);

INSERT INTO Seguridad.RolPermiso (IdRol, IdPermiso)
SELECT R.IdRol, P.IdPermiso FROM Seguridad.Rol R CROSS JOIN Seguridad.Permiso P
WHERE R.NombreRol='ANALISTA_GRADOS' AND P.CodigoPermiso='TRAMITE.CONSULTAR'
  AND R.Activo=1 AND P.Activo=1
  AND NOT EXISTS (SELECT 1 FROM Seguridad.RolPermiso RP
                  WHERE RP.IdRol=R.IdRol AND RP.IdPermiso=P.IdPermiso);
INTEGRACIÓN: el catálogo institucional y los roles nativos no se sincronizan automáticamente.
